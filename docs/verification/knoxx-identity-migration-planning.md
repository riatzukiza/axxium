# Whole Knoxx identity migration verification contract

This is future implementation acceptance for Axxium issue 6, UUID `axxium-knoxx-identity-migration`, unchanged Todo/P0/8. The six original requirements and four acceptance criteria remain controlling. No backend test, credential operation, database migration, cookie flow, provider login or deployed integration has been performed by this planning change.

## Required source and admission preconditions

Before implementation, bind both owners' exact reviewed source, current receiving route, planning decisions and lawful native Ready admission. Axxium currently uses npm/package-lock and Knoxx pnpm; retain those policies. Record full current source and mandatory suite discovery, not an old test count or compiler exit alone. Both repositories require zero warnings, zero failures and zero errors. Missing dependency/tool, empty suite, admission failure or unavailable environment is a visible hold. Review actor row/claim normalization, issuer/audience/key trust, authenticated capability mapping/freshness, cookie routing/CSRF and existing account migration/rollback choices before code.

## Explicit status and rollback verification additions

The proposed Axxium-owned `POST /api/auth/introspect`, `axxium.identity-status.v1` contract in the design is a prerequisite, not a currently implemented `/api/auth/me` feature. On both portable hosts, test exact version/authority/actor/session/capability/time shapes and distinguish rejected/expired/revoked/inactive authentication (401), verified insufficient grant/policy (403), and unknown/unimplemented/unavailable/malformed or untrusted status evidence (503). Axxium-side actual endpoint fixtures inject verifier/database failure and assert retryable refusal rather than 401; absent/expired/revoked sessions retain their distinct rejected reason. Knoxx-side real request/UI fixtures keep loading/retryable error separate from signed-out and prove no stale capability, forged source, cookie/Bearer conflict, cache expiry or unknown version can admit DB/tool/conversation effects. A HTTP 200/shape-only positive and a decoded token without authority are deliberate negative controls.

Bind migration recovery to cutover epoch and authenticated per-account account/credential revision watermarks separately from session/capability status revisions. Future rollback fixtures must change/reset a password, rotate/revoke a session and API key, remove a capability, disable an account, and create/accept an account after cutover. Assert stale scrypt credentials, old tokens/keys and revoked privileges remain refused; authorized users and post-cutover users retain exact identity/resources without re-registration. Cover provider-only/bootstrap/machine kinds, concurrent changes, replay, duplicate/reordered/missing revisions, stale/wrong-authority/wrong-epoch evidence and interrupted recovery. The primary consumer-route rollback retains qualified Axxium authentication; attempted legacy-authority rollback without a separately reviewed complete freeze/watermark proof is a negative control. Verify no BCrypt-to-scrypt back-import, credential resurrection, email-only relinking, deletion/stranding of new users or silent fallback on status outage. Missing accepted evidence/protocol stays a visible cutover/rollback hold.

## Pure laws first, adapters second

Author RED tests for `.cljc` admission/authorization and migration decisions on JVM and compiled CLJS, feeding explicit verified/unverified evidence, clock, capabilities, tenant facts and migration state. Cover normalization equivalence and refusal for incomplete/ambiguous facts, monotone restriction of grants, exact subject rather than email linking, deterministic conflict decisions, idempotent replay, race outcomes and retirement prerequisites. The portable layer must have no filesystem/environment/network/clock/JS dependency inward. Review the actual selected runners and test namespaces before running; the accepted Axxium tree currently has a compiled `axxium\..*-test$` target but no tracked test namespace or JVM portability runner. Add real test infrastructure in the implementation scope; do not claim current dual-host discovery.

Adapter RED tests must exercise real request admission, schema normalization, Axxium JOSE/session/database behavior and Knoxx policy/UI/storage boundaries. Assert refusal occurs before writes or downstream tool effects, not merely that an error value exists. Use controlled private database and HTTP/browser fixtures only after implementation authorization; record actual route registrations and discovered assertions. Retain existing Knoxx identity, auth-session, authz and method-policy tests, including remote-role rejection, collision refusal and tenant/resource controls. Future selected migration/capability tests add assertions rather than replacing inconvenient existing tests.

GREEN implements only the reviewed pure laws and owner adapters. Rerun focused laws and full relevant suites, typecheck/production artifacts, current boundary and lint gates. No example baseline or mocked provider completes real integration. Scope changes require renewed planning; an inability to satisfy the whole account migration or retirement criteria stays blocked.

## Migration, coexistence and removal proof

Run isolated dry-run and migration using owned synthetic legacy/Axxium stores with account-kind counts, immutable mapping/decision IDs and resource-attribution comparisons. Credentials/tokens/keys must not appear in logs, artifacts, snapshots or receipts. Prove retry, interrupted import, concurrent login and conflict resume are safe. Store a checkpoint on partial failure and separate proof-backed continuation from destructive removal. Test the coexistence mode selector, final cutover admission, revocation/expiry across both old and new sessions and rollback at each eligible stage. Prove old bootstrap or background writers cannot resurrect standalone auth state after removal. Final store inventory demonstrates no standalone Knoxx auth collections/tables; evidence includes writers and live selected schema, not just empty fixtures.
