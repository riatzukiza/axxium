## Complete future commands and human proof

Axxium accepted scripts: `npm run typecheck`, `npm run build`, `npm test`, `npm run boundary:check`; lint current `src` and tests with the configured optional clj-kondo linters and zero warnings, and run deployment-boundary self-test/check as hosted CI requires. Require a nonempty meaningful test suite with explicit test/assertion/failure/error counts; compiler exit 0 alone is not a pass. Existing accepted gaps or absent tools stay visible, not silently waived.

Proxx accepted scripts and instructions require `pnpm build`, `pnpm typecheck`, `pnpm test`, `pnpm test:cljs`, `pnpm test:cljs-runtime`, `pnpm check:no-new-typescript`, and clj-kondo on `src/proxx test/proxx`; `pnpm lint:errors` and schema test `npx tsx --test src/tests/schema-migration.test.ts`. The actual frontend gates are `pnpm web:build`, `pnpm web:test`, `pnpm web:test:e2e`. Preserve required proxy smoke `npx tsx --test src/tests/proxy.test.ts` with an explicitly owned synthetic `PROXY_AUTH_TOKEN`; never source the AGENTS example's shared Services environment or read real provider/billing secrets. Run relevant request-auth, SQL credential store, tenant API-key, OAuth/refresh and federation tests, full `pnpm test`, and actual isolated `test:e2e`, multitenancy and federation/audit scripts when their current prerequisites apply. Inventory current hosted main/staging gate obligations at the implementation head, including coverage threshold/immutable container checks; percentages and skipped contexts are not substitute approvals. Current test:coverage excludes routes, oauth-routes and native-auth, so that percentage alone does not measure migration ingress: require explicit meaningful HTTP/WS/SSE/browser regressions and complete selected-input proof. Do not narrow the AGENTS required checks because this matrix is documentation.

All integration resources need unique private ports, DB/service identifiers, runtime/home/temp/cache and owned cleanup. Synthetic providers/identity endpoints establish local contract behavior; they do not supply production issuer trust or a human federated-login pass. Human verification must cover authenticated real mounted browser login/callback, account continuity without forced re-registration, tenant/key management, both provider OAuth modes, refresh/logout/revocation, policy denials and rollback under authorized isolated operational fixtures. Record unavailable provider/operator prerequisites as blockers, never fake a login, suppress a failing suite or mutate shared resources. Qualified Services staging at exact merge and independent production admission are separate from this migration test result.

## Proposed recovery and authority-status controls

These are additional future acceptance controls for step 7/R1–R6 and AC1–AC4, not tests executed by this documentation correction. Bind every fixture to the chosen migration epoch, authenticated authority provenance, source head/base/merge and before/after watermarks.

| Recovery or verification case | Required future evidence |
| --- | --- |
| Post-cutover users and invitations | Preexisting, newly created, invited-but-pending, accepted-invitation and Axxium-only users retain authorized access, memberships and product attribution across consumer rollback/forward repair, without re-registration, duplicate identities or repeat owner/admin bootstrap. No old local row is required for a new canonical user. |
| Concurrent post-checkpoint change | Linking/unlinking, changed stable-provider identity attribution, credential/session/client rotation or revocation, suspension/deletion, capability/role reduction, membership/invitation/tenant selection and tenant-key rotation/scope change/revocation are reconciled from qualified owning changes. Paused recovery, duplicate delivery and concurrent writes preserve ordering/idempotency; stale snapshots, missing watermarks, unknown writer or conflicting mappings refuse admission. |
| Recovery authority and retirement | Positive compatible rollback keeps Axxium authoritative; incompatible or unverifiable restoration fails closed until forward repair. Before/after irreversible retirement controls show no resurrected local session/role/key, lost new user, orphaned membership/FK/DID/usage/provider-owner join, unintended elevation or parallel identity writer. A successful SQL restore alone is insufficient. |
| Provider/product continuity | Factory/OpenAI browser/device pending-state, callbacks/reauth/refresh/account removal and every provider credential kind preserve local ownership, actor/tenant binding and current policy through recovery. Cross-actor/tenant, changed provider identity, revoked permission or stale callback state refuses persistence without exporting provider/billing secrets. |
| Versioned verification response | Actual kernel-origin claim construction normalizes raw rows and binds issuer/audience/subject/actor/entity/session, active status, current capabilities and freshness. Validate current response versions and permissioned capability changes. Wrong issuer/shape/version/status, stale revocation/capability evidence, unauthorized mutation and signature-only downgrade all fail before protected effects. |
| Public refusal versus unavailable authority | Independently exercise proposed 401 invalid/missing/expired/revoked authentication, 403 verified-but-denied capability/membership/resource, and 503 timeout/unavailable/malformed/unknown-version/unverifiable-current-status authority. Reviewed suspended/retired-actor classification is consistent. No 200-to-allow coercion, anonymous/local credential fallback, stale-cache permission grant, protected effect or identity/key disclosure; streaming revocation is separately exercised. |

All earlier full backend/CLJS/schema/boundary/frontend/human gates remain required. Mock status responses or synthetic recovery fixtures do not qualify production identity trust, real login continuity, operational rollback or Services staging. Owner decisions for migration epoch/provenance, recovery mode, response/error version and cache/revalidation bounds remain explicit before implementation.
